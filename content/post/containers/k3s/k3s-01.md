K3s is a <a href="https://landscape.cncf.io/">CNCF</a> sandbox project that delivers a lightweight yet powerful certified Kubernetes distribution.
K3S is a lightweight Kubernetes, easy to install, Simple but powerful "batteries-included" features have been added, such as:

- local storage provider
- service load balancer
- helm controller
- Traefik ingress controller

## What K3s actually is

K3s is a CNCF-certified Kubernetes distribution packaged as a single binary of roughly 50 MB. It is not a fork of Kubernetes — it is upstream Kubernetes with the parts a single-node or edge deployment does not need removed or replaced:

- **etcd is optional.** By default K3s uses an embedded SQLite datastore instead of etcd, which is what makes a single-node install trivial. For HA you switch to embedded etcd or an external datastore.
- **Ingress is built in.** Traefik is deployed as part of the cluster, so a fresh install can serve HTTP/HTTPS traffic immediately.
- **Storage is built in.** A local-path provisioner creates PersistentVolumes on the node's disk without any extra CSI driver.
- **Helm is built in.** A Helm controller watches HelmChart CRDs, so you can declaratively install charts by dropping a manifest in `/var/lib/rancher/k3s/server/manifests/`.

The trade-off is that you give up some flexibility: you cannot easily swap the datastore, ingress or storage provider, and the control plane is not highly available unless you configure it to be. For a home lab, an edge site, or a CI runner, that trade-off is usually worth it.

## After the install

The kubeconfig lives at `/etc/rancher/k3s/k3s.yaml` and is owned by root. Either copy it to your user's `~/.kube/config`, or set `KUBECONFIG=/etc/rancher/k3s/k3s.yaml`. From there, `kubectl get nodes` and `kubectl get pods -A` are the two commands that tell you whether the install actually worked.

The install script also drops a token at `/var/lib/rancher/k3s/server/node-token`. You will need it if you later add worker nodes with `K3S_URL=https://<server>:6443 K3S_TOKEN=<token> sh -`.

## Caveats

- This is a **single-node** control plane. If the node dies, the cluster dies. For anything you care about, run three server nodes.
- The `get.k3s.io` script pulls the latest stable release. Pin a version with `INSTALL_K3S_VERSION=v1.x.y` if you need reproducibility.
- K3s defaults to the `local-path` storage class, which provisions hostPath volumes. That is fine for a lab and wrong for anything multi-node.
